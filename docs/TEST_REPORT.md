## فحوص الإنتاج المضافة

- المتصفح لا يرسل apikey ولا يتصل بمسارات Supabase Auth أو REST؛ MFA والتحديث والخروج والأرشيف تمر عبر FastAPI.
- اختبارات إضافية لرفض AAL1 عن الأرشيف والإحصاءات، وعدم حذف عامل MFA موثّق عبر مسار تنظيف التسجيل، وعزل النقل عن مفتاح الخادم.
- فحص متغيرات الإنتاج يرفض HTTP وloopback وwildcard ومسارات CORS والمفاتيح الناقصة؛ Development يسمح HTTP على loopback فقط.
- الأرشيف يحافظ على عدد النتائج ونهاية اليوم UTC الشاملة. ACK الحدث يطابق event_id بعد نجاح RPC.
- خادم الواجهة يعرض index.html دون كشف ملفات server أو مفاتيح البيئة.
- أصلح اختبار المهلة سباقًا بين polling وانتهاء النافذة: يثبت أولًا تعطيل القرار دون تغيير حالة الحدث محليًا، ثم يسمح باستجابة timeout من الخادم المحاكى.
- Docker غير متوفر في هذه البيئة؛ لم نبنِ صورته محليًا. أضيفت خطوة بناء في CI، ولم تُنفذ GitHub Actions أو Render بعد.

## نتائج أساسية

- صفحة التشغيل بلا إعدادات لا تسمح بالدخول، ولا يوجد Demo أو حساب أو رمز تجاوز داخل index.html.
- ID وكلمة المرور لا يفتحان لوحة البيانات وحدهما؛ أول دخول يمر بإعداد عامل المصادقة، والدخول التالي بتحدّيه.
- رمز خاطئ يُظهر الخطأ ويُبقي البيانات مخفية. التحقق الصحيح يكمل الانتقال باستخدام جلسة تستوفي شرط الخادم.
- API ترفض قراءة/مراجعة/تذكرة اتصال من AAL1 حتى لحساب admin، وتطابق هوية Auth مع سياق JWT داخل DB.
- RLS تمنع قراءة الجداول والصور من AAL1؛ حساب معطل يبقى ممنوعًا حتى مع AAL2.
- كلمات المرور لا تُكتب في سجل النشاط أو ربط المعرفات؛ ID غير معروف/كلمة مرور خاطئة/عضوية معطلة لها رسالة عامة متطابقة.
- محدد المحاولات مخزن في PostgreSQL، وليس مؤقت متصفح.
- صورة الحدث تعرض دون قص، والصور المرفوعة تتحقق بايتاتها وحدود حجمها؛ أخطاء الصورة لا تحوّلها إلى دليل بديل مزيف.
- قبول/رفض/Timeout وحفظ القرار وعدم تبديل القرار النهائي وإعادة الإرسال الآمنة اجتازت اختبارات API/SQL/الواجهة.
- فصل الأرشيف عن المراقبة، البحث بالحالة، مرجع الأحداث، JSON، ونموذج حساب مدير نجحت.
- إحداثيات الهدف مختلفة عن GPS الدرون، no_fix لا يرسم كإحداثيات صالحة، والموقع الصفري يُقبل عند صلاحيته.
- التليمترية الموسعة تُحفظ وتضيف التاريخ، والعينة الأقدم ترفض دون إضافة مسار خاطئ.
- المسافة الأفقية المحسوبة اختُبرت بقيمة مرجعية، وHDOP لا يعرض كخطأ بالمتر.
- انقطاع الخدمة يوقف القرارات، والتليمترية المتقادمة توقف الأوامر.
- مدخلات HTML خبيثة تظهر كنص، ولا تنفذ كودًا؛ اختبار شاشة390 و320px لا يمدد الصفحة أفقيًا.
- الخروج يمسح البيانات والجلسة والأسرار المعروضة، ويُجهض الطلبات المعلقة؛ تغيير hash أو إعادة التحميل لا يسترجع جلسة محفوظة.
- لا أخطاء JavaScript غير معالجة خلال السيناريو النهائي.

## ما لم يُختبر بعد

- المسار الكامل عبر HTTP مع مفاتيح الخادم وSupabase Auth، ومزود TOTP على هاتف فعلي، ورفض إعادة استخدام الرمز/انتهاء صلاحيته من خدمة Auth الفعلية. اختبارات SQL المستضافة موضحة أدناه.
- نشر GitHub Pages/Render أو VPS، HTTPS/CORS/Proxy/حدود الاستضافة، وأداء الاتصالات عبر الإنترنت.
- أجهزة GPS أو كاميرا أو طائرة فعلية، ودقة موقع الهدف أو الوحدات/المراجع من مصدر التليمترية.
- تحميل بلاطات خريطة عبر الإنترنت؛ اختبارات الخرائط تتحقق من العلامات والمسافات والحقول، دون طلب بلاطات عامة.
- اختبار تحميل/اختراق شامل، ومزامنة عدة خوادم، واستعادة النسخ الاحتياطية.

**الاختبارات المحلية والتحقق من SQL المستضاف لا تعني أن الموقع أو الطائرة متصلان.** اختبارات القبول الفعلي في ACCEPTANCE_AR.md هي البوابة التالية بعد قرار الربط.

## ملاحظات عملية

- ظهر تحذير إهمال من FastAPI/Starlette في أداة TestClient حول الانتقال المستقبلي إلى httpx2؛ لم يفشل أي اختبار، ولا يغيّر بروتوكول تشغيل Uvicorn.
- واجهة طلبات الاختبار الشبكية تولد/تتحقق رمز TOTP ضمن fixture فقط لاختبار تدفق الشاشة؛ في الإنتاج Supabase Auth هي جهة التحقق. QR الظاهر في fixture اختبار لا يُستخدم لإنشاء حساب حقيقي.
- لقطات previews صادرة عن اختبار فعلي للواجهة مع بيانات اصطناعية وصورة موسومة TEST IMAGE. ليست صورًا لطائرة أو موقع تشغيل حقيقي.
- مكتبة Leaflet1.9.4 محلية داخل ملف النشر، مع الرخصة في vendor. لا إطار واجهة كبير.

## إعادة التشغيل على جهازك

من مجلد المشروع، بعد تثبيت Python وNode.js لأدوات الاختبار فقط:

```powershell
python -m venv .test-venv
.\.test-venv\Scripts\python.exe -m pip install -r tests/requirements.txt
.\.test-venv\Scripts\python.exe -m pytest tests -q
npm ci --prefix tests
```

من مجلد tests:

```powershell
npx playwright install chromium
node browser.cjs
node database.cjs
```

اختبار المتصفح يفتح خادمًا محليًا على127.0.0.1:8770 ويغلقه بعد النجاح. يتطلب تنزيل Chromium مسبقًا. لا تعدّل CONFIG للقيام بهذه الاختبارات؛ يحقن الاختبار إعدادات خاصة في الرد المحلي فقط. ملف index.html يبقى بلا مفاتيح/حسابات وهمية.

نتائج الآلة: tests/browser-results.json وtests/database-results.json. وصف المسارات المحدث في docs/openapi.json.

- المرجع `rxqlccksknrjysluzgkt`، أربع مهاجرات ناجحة، 12 جدولًا عامًا وكلها RLS.
- معاملة اختبار service_role: حفظ حدث 201، إعادة متطابقة 200، اختلاف بصمة 409، نافذة مراجعة 20 ثانية. حفظ التليمترية 200 ورفض الطابع الزمني نفسه 409. أُلغي الاختبار بـROLLBACK دون إبقاء سجلات اختبار.

- مخزن event-images خاص، 10485760 بايت، JPEG/PNG/WebP. لم يُختبر رفع صورة عبر Storage HTTP بعد.
- Advisor بعد الإصلاح: لا WARN/ERROR في فحصي security/performance؛ بقيت INFO لثلاثة جداول خادم بلا سياسات عميل، و12 فهرسًا لم يُستخدم بعد. تفسيرها وروابطها في CLOUD_STATUS_AR.md.
- الأحداث والملفات الشخصية صفر بعد الاختبار. لا حساب مدير أو جلسة Auth حقيقية أنشئت.
