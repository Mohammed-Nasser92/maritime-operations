# مرصد — Maritime Operations v3.1

كود مهيأ للتشغيل عبر: **FastAPI + Supabase Auth/MFA + PostgreSQL + Storage**.
الواجهة عربية RTL، ولا تتضمن وضع Demo أو حسابًا افتراضيًا أو بيانات تشغيل مضمّنة.

**حالة النشر (30 سبتمبر 2026):** مشروع Supabase الحقيقي مهيأ في فرانكفورت، وحساب المدير الأول أُنشئ وربط بمعرّف دخول. هذا مستودع المصدر: https://github.com/Mohammed-Nasser92/maritime-operations . لم يُنشر الموقع أو FastAPI بعد؛ Render مؤجل حتى اختبار المستخدم محليًا، وربط الدرون أخيرًا. راجع `docs/CLOUD_STATUS_AR.md` و`docs/PREVIEW_AND_GITHUB_AR.md`.

البنية: المتصفح → FastAPI → Supabase Auth/PostgreSQL/Storage. لا توجد مفاتيح Supabase في المتصفح. صورة الحدث فقط تُحمّل برابط Storage موقّع قصير الصلاحية.

## البداية الآن (قبل ربط الخدمات)

1. افتح مجلد المشروع في VS Code.
2. من Terminal داخل المجلد شغّل `python -m http.server 8001 --bind 127.0.0.1`.
3. افتح http://127.0.0.1:8001 لمراجعة شاشة الدخول.
4. عدم توفر الإعدادات يُظهر «بانتظار تهيئة الاتصال» ويوقف الدخول عمدًا.
5. راجع مجلد `previews` لصور الأقسام الناتجة من اختبارات محلية؛ الصور موسومة ببيانات اختبار.

لا يوجد ID أو password تجريبي في الموقع. لا نفتح لوحة البيانات قبل مصادقة حقيقية.
يمكن تشغيل اختبارات الواجهة بمحاكاة الشبكة المعزولة الموجودة في `tests/browser.cjs`؛ هذه المحاكاة لا تدخل ملف النشر.

## الأقسام

- **لوحة المراقبة:** صورة الحدث، قبول/رفض/تفاصيل، طابور مراجعة، إحصاءات، بيانات الدرون وخريطة المواقع.
- **التتبع والموقع:** آخر GPS للدرون، علامة منفصلة للهدف، دقة الهدف إن أرسلها المصدر، ومسار آخر 600 عينة للمهمة.
- **مرجع الأحداث:** بطاقات آخر 24 حدثًا، صور وتفاصيل JSON، ودليل معاني الحقول والتصنيفات.
- **الأرشيف:** بحث بمعرّف الحدث الكامل وتصفية بالنوع والحالة والتاريخ UTC وصفحات.
- **الأوامر:** القدرات التي يعلنها النظام المتصل فقط، طلب مع سبب وتأكيد، وتاريخ الحالة.
- **الإدارة:** حسابات المدير، إضافة حدث اختبار وصورة، سجل النشاط، إدارة وصول المشغّلين الموجودين سابقًا.

الحساب الجديد مدير واحد يستخدم جميع الأقسام من جلسة واحدة. الحسابات القديمة لا تُرقّى تلقائيًا، حفاظًا على الصلاحيات الموجودة.

## الدخول الحقيقي

1. ID + password: يتحقق الخادم من معرّف الدخول الخاص ويطلب جلسة Supabase.
2. Authenticator: إعداد QR/مفتاح يدوي أول مرة، أو رمز TOTP ذي 6 أرقام لاحقًا.
3. الخادم وقاعدة البيانات والصور تشترط `aal2` حتى لو كان الحساب مديرًا؛ إخفاء الصفحة ليس الحماية الوحيدة.
4. الجلسة في ذاكرة الصفحة فقط؛ إعادة تحميل الصفحة تستلزم دخولًا جديدًا.
5. فقدان المصادقة/كلمة المرور يُعالج عبر مالك مشروع Supabase، وليس زر تجاوز أو حسابًا مخفيًا.

خطوات الإعداد: `docs/DEPLOYMENT_AR.md`. المراجعة الأمنية وحدود الاختبارات: `docs/TEST_REPORT.md`.

## تحديد الموقع

GPS المثبت بالدرون يحدد موقع الدرون فقط. إحداثيات الهدف `latitude/longitude` يجب أن يرسلها Phase 1/2 مع `location_validity`، ولا ينسخ الموقع إليها تلقائيًا. `drone_latitude/drone_longitude` موقع الطائرة عند الكشف، ومختلف عن موقعها الحالي.

دائرة دقة الهدف تظهر فقط عند إرسال `target_accuracy_m`. HDOP قيمة جودة هندسية، وليست خطأ بالمتر. المسافة إلى المنزل تُعرض من الطائرة، أو تُحسب أفقياً من GPS المنزل والطائرة عند توفرهما؛ المسافة المقطوعة لا تُخمن. `altitude_m` ارتفاع بالمتر كما يرسله المصدر؛ يجب تثبيت مرجعه (عن سطح البحر/الأرض/نقطة الإقلاع) مع المرحلة الثانية قبل الربط.

الخريطة تعمل بعلامات جغرافية وشبكة دون خلفية خارجية. زر «تحميل خريطة الشوارع» يطلب بلاطات OpenStreetMap عبر الإنترنت لمنطقة العرض؛ لا يرسل أحداثًا أو صورًا أو أسرارًا. يلزم الالتزام بسياسة المزود وتغيير المزود/الاستضافة عند التوسع. لا تحميل جماعي أو offline cache للبلاطات.

## ما لم يحدث بعد

لم تُنشأ حساباتك الخارجية، ولم تُنفّذ ملفات SQL في Supabase مستضاف، ولم يُنشر الخادم أو GitHub Pages، ولم تُربط طائرة/GPS/كاميرا فعلية. اختبارات API تستخدم بديلًا للخدمة، واختبارات SQL تنفذ على PostgreSQL محلي PGlite. فحص Authenticator على هاتف فعلي والتكامل المستضاف مطلوبان بعد الربط، ولا يجوز اعتبار هذا التقرير إثباتًا لهما.

هذا تحديث للحزمة الجديدة فقط؛ مشروع SQLite القديم لم يُحذف ولم يُعدّل. لا تطوير YOLO أو ArduPilot أو أوامر طيران هنا.

## الانتقال إلى الإنتاج

الخادم يقدم index.html من `/`، والواجهة تستخدم رابط الصفحة تلقائيًا. إعداد GitHub Pages المستقل يحتاج phase2ApiUrl فقط. إعدادات Development/Production وشرح المفاتيح وGitHub وRender في DEPLOYMENT_AR. لا تخزن الصور أو SQLite على نظام ملفات Render.

REST الأحداث والصور جاهز لاختبار التكامل، لكن WSS الخاص بJetson والطابور الدائم وربط follow/resume ما زالت أعمال مرحلة Level 2. لا يوجد Production URL حتى نشر الخدمة فعليًا.
